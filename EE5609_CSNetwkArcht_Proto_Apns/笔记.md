# 计算机网络学习笔记

## Q: 为什么窗口为 N 的链路利用率公式是 U = N/(1+2a)？

**A**: 链路利用率是指**发送的效率**，而不是完成整个周期的效率。

- 窗口 N 表示可以同时发送 N 个帧
- 发送 N 个帧需要时间：N × T_frame
- 整个周期时间（从开始发到收到最后一个 ACK）：T_frame + 2×T_prop
- 但利用率只看"有效发送时间占比"，所以 U = N×T_frame / (T_frame + 2×T_prop) = N/(1+2a)

---

## Q: CSMA/CD 为什么最小帧长要 ×2 来回时间？

**A**: 因为最坏情况是 A 的信号快到了 B 才开始发送。

时间线：
- t=0: A 开始发帧
- t=T_prop: A 的信号刚到 B，此时 B 也开始发（B 监听信道还是空的）
- t=2×T_prop: 碰撞信号传回 A，A 才能检测到碰撞

所以帧长必须 ≥ 2×T_prop，否则 A 发完了还不知道撞了。

## Q: 为什么以太网限制最小帧长 64 bytes？

**A**: 基于最坏情况的物理设计。

最坏情况参数：
- 铜线最大传输距离 500m（再远信号衰减到无法检测）
- 4 个中继器是极限设计，每个延迟 2μs
- 5 段 × 500m，信号传播速度 2×10⁸ m/s
- 单段传播延迟 = 500/(2×10⁸) = 2.5μs

计算：
```
往返时间 = 2 × (5 × 2.5μs + 4 × 2μs) = 2 × (12.5 + 8) = 41μs
@ 10Mbps → 41μs × 10Mbps = 410 bits ≈ 64 bytes
```

IEEE 802.3 标准规定最小帧长 64 bytes（512 bits），更长的数据传输需要光纤或其他材料。

## Q: IP 切片的要点？

**A**:

1. **Offset 除以 8 的原因**：IP 头里只留了 **13 位**存 Offset 字段。若以字节为单位，覆盖 64KB 需要 2¹⁶ 位；除以 8 后 2¹³ 就够了。代价是**强迫每片数据都是 8 字节的倍数**（否则下一片的 Offset 除不尽）。

2. **Offset 只记录原始 payload 中前面已有字节的"8 字节倍数"**：因为目的端**拼接的是数据部分，不需要中间那些头**。头只是传输过程的信使——用来记录 ID/Offset/MF 这些信息，**只在传输过程中需要，到达后立即丢弃**，不参与重组拼接。

**图**（4000B 数据报过 MTU=1500 链路）：

```
原始数据报 (4000B = 20头 + 3980数据)
┌────┬──────────────────────────────────────┐
│头20│            payload 3980B             │
└────┴──────────────────────────────────────┘
              │ 路由器分片 (每片数据≤1480, 8的倍数)
              ▼
片1: ┌────┬──────────────┐  len=1500  Offset=0    MF=1
     │头20│ 数据 0–1479  │
     └────┴──────────────┘
片2: ┌────┬──────────────┐  len=1500  Offset=185  MF=1   (1480÷8)
     │头20│数据1480–2959 │
     └────┴──────────────┘
片3: ┌────┬──────────┐     len=1040  Offset=370  MF=0   (2960÷8)
     │头20│数据2960–3979│
     └────┴──────────┘
              │ 各片独立路由（可能乱序到达）
              ▼
目的主机: 按 ID 认亲 → 按 Offset×8 排位 → 见 MF=0 知收齐
          → 剥掉各片的头(丢弃) → 只拼数据 → 还原 4000B 数据报
```

## Q: Go-Back-N vs Selective Repeat？

**A**（大题骨架表）:

| | Go-Back-N | Selective Repeat |
|---|---|---|
| 发送窗口 | N | N |
| **接收窗口** | **1** | **N（需缓存乱序帧）** |
| 出错后重传 | 出错帧 + 之后所有帧 | **只重传出错帧** |
| 接收方复杂度 | 简单（按序交付，无缓存）| 复杂（缓冲 + 重组排序）|
| 带宽效率 | 低（好帧被陪葬重传）| 高 |
| 出错通知 | 丢弃乱序帧 + 重发累积ACK | NAK n 显式点名 |

**帧2丢失场景**：
- GBN：接收方对到达的帧3、4 **丢弃**，重发 ACK1（水位线）；发送方超时后**从帧2起重传 2,3,4**。
- SR：接收方把 3、4 **缓存**，回 NAK2；发送方**只补帧2**，然后 2,3,4 按序交付。

### Q: 为什么序号空间 GBN ≥ N+1、SR ≥ 2N？

都是"ACK 全丢"最坏情况逼出来的**新旧帧歧义**问题：

- **GBN (K ≥ N+1)**：接收窗口=1。若 K=N：发 0..N−1 全部正确到达，接收方期望序号绕回到 0；ACK 全丢 → 发送方重传 0..N−1 → 接收方分不清帧 0 是新是旧，错误接收。K ≥ N+1 时重传的旧帧序号必落在期望序号之外，被丢弃。
- **SR (K ≥ 2N)**：接收窗口也有 N 大，歧义范围翻倍。ACK 全丢后发送方重传 [0..N−1]，接收窗口已滑到 [N..2N−1]；若 K < 2N 两窗口在序号环上重叠，旧帧会被当新帧收进缓存。K ≥ 2N 保证发送/接收窗口永不重叠。

一句话：**GBN 接收方只认 1 个序号，躲 1 步就够（N+1）；SR 接收方认 N 个序号，要躲开整个窗口（2N）。**

### Q: NAK n 是什么？和累积 ACK / 水位线的关系？

- **NAK n** = 显式拒绝："帧 n 缺了，请只重传 n"。SR 用它点名补一个。
- **GBN 的 ACK 是累积的**：ACK k = "k 及以前全收到" = **水位线**。ACK 前进一格，发送窗口底部滑一格。收到乱序帧时接收方不发新 ACK，只重发上次水位线（dup-ACK），发送方靠超时/重复 ACK 触发"从水位线起全部重传"。
- 课件中 GBN 也支持 NAK 触发重传（ARQ 机制之一），但主线是累积 ACK + 水位线。

## Q: TDMA/FDMA/CDMA 是什么？

一间屋子（=信道）很多人同时说话，三种"分开"的办法：
- **FDMA 频分**：按**音高**分——你用低音区、我用高音区，同时说互不干扰（=收音机电台按频率分开）
- **TDMA 时分**：按**时间**分——轮流说，每人一个时间片（=课堂点名发言）
- **CDMA 码分**：每人说**不同语言**——同时同频段说话，但听者只懂自己那门语言，用"码"把信号过滤出来（=3G 移动通信）。每个节点分到唯一码片序列，发送=数据×码片，接收=信号与自己的码片做内积，别人的码正交→内积为0→被滤掉

共同点：**静态预分配**。所以高负载无碰撞，低负载时切给你的份没人用也浪费。

## Q: ALOHA → Slotted ALOHA → CSMA 是递进关系吗？各自机制？

**是递进：每一代解决上一代的痛点。**

```
Pure ALOHA        想发就发，撞了随机等再重发     效率 18%
   ↓ 加时隙对齐（碰撞窗口从2帧减到1帧）
Slotted ALOHA     只能在槽首发，撞了以概率p重发   效率 37%
   ↓ 加"先听后发"（明知有人说话就别撞上去）
CSMA              听信道：空闲→发；忙→等          仍有碰撞(传播时延)
   ↓ 有线：加"边发边听+撞了中止"
CSMA/CD           以太网 802.3
   ↓ 无线：听不准也发时听不见 → 改为"预约+确认"
CSMA/CA           WiFi 802.11（RTS/CTS + ACK）
```

### Pure ALOHA 机制与效率推导

**机制**（1970s 夏威夷大学无线网络）：
1. 帧到达 → **立即发送**，不同步、不监听
2. 收不到 ACK（=撞了）→ 等**随机时间**重发
3. 关键：在 t₀ 发的帧，会与 **[t₀−1, t₀+1] 共 2 个帧长窗口**内的任何发送重叠：
   - 别人在 (t₀−1, t₀) 开始发的，帧还没发完，和你尾部重叠
   - 别人在 (t₀, t₀+1) 开始发的，和你头部重叠

**效率计算**（列式）：
- 设 G = 每帧时长内平均发送尝试数（含重发），尝试服从泊松分布
- 吞吐量 S = 尝试率 × 成功概率。一次发送成功 ⇔ 2 帧长窗口内没有其他尝试
- 窗口内"其他尝试数"服从均值 2G 的泊松分布，为 0 的概率 = e^(−2G)
- **S = G·e^(−2G)**
- 求导：dS/dG = e^(−2G)(1 − 2G) = 0 → **G\* = 1/2**
- S_max = (1/2)·e^(−1) = **1/(2e) ≈ 0.184 ≈ 18%**

### Slotted ALOHA 机制与效率推导

**机制**：
1. 时间切成等长时隙（1 隙 = 发 1 帧的时间），所有节点**同步**
2. 只能在**槽首**发送；新帧到达 → 等下一个槽
3. 碰撞（同槽 ≥2 个节点发，所有节点都能检测到）→ 之后每个槽以**概率 p** 重发，直到成功（随机化防止两个节点永远同步对撞）
4. 碰撞只可能发生在**同一个槽内** → 碰撞窗口 = 1 帧长（Pure 的一半）→ 效率翻倍

**效率计算**（列式）：
- N 个节点，每节点每槽以概率 p 发送
- 某节点成功 = 自己发 × 其他 N−1 个都不发 = p(1−p)^(N−1)
- 任一节点成功（=槽被有效利用）：**E = N·p·(1−p)^(N−1)**
- 对 p 求导找最大：d/dp[p(1−p)^(N−1)] = (1−p)^(N−2)[(1−p) − p(N−1)] = 0
  → 1 − p = p(N−1) → **p\* = 1/N**（直觉：N 人平分机会）
- 代入：E_max = N·(1/N)·(1−1/N)^(N−1) = (1−1/N)^(N−1)
- N→∞ 用极限 lim(1−1/N)^N = 1/e → **E_max = 1/e ≈ 36.8% ≈ 37%**

### ALOHA 效率推导（完整版）

**统一设定**：帧长 = 1 个时间单位；G = 每帧时长内平均总发送尝试次数（含重传）。
大量节点独立随机发送 →"大量独立小概率事件之和"的极限就是泊松：
Binomial(N,p)，N→∞ 且 p=G/N ⇒ P(恰好 k 次) = G^k·e^(−G)/k!，特别地 P(0 次) = e^(−G)。
（泊松只是二项极限的快捷记法，下面全部用二项硬推。）

#### Pure ALOHA：脆弱窗口 = 2 个帧长

一帧占用 [t, t+1]。别人在 t' 开始发送，与我 [t₀, t₀+1] 重叠 ⇔ t' ∈ (t₀−1, t₀+1)：

```
别人在 t₀−0.9 发: [t₀−0.9 ── t₀+0.1]   他的尾 撞 我的头 → 碰撞
别人在 t₀+0.9 发:        [t₀+0.9 ── t₀+1.9]  他的头 撞 我的尾 → 碰撞
别人在 t₀−1.1 发: [t₀−1.1 ─ t₀−0.1]    已发完，不重叠 → 安全
别人在 t₀+1.1 发:              [t₀+1.1 ─ t₀+2.1]  还没撞到我 → 安全
```

**逐步推导**：
1. 我 t₀ 发送，成功 ⇔ 长度 2 的窗口内其他 N−1 个节点都不发
2. 一个节点每帧时长以 p=G/N 发送 → 在 2 个帧长内不发 = (1−p)²
3. 其他 N−1 个全不发 = (1−p)^(2(N−1))
4. 代入 p=G/N 并取极限：(1−G/N)^(2(N−1)) = [(1−G/N)^N]² × (1−G/N)^(−2) → (e^(−G))² × 1 = **e^(−2G)**
5. 吞吐量 S(G) = 尝试率 × 每次成功概率 = **G·e^(−2G)**
6. 求导：S'(G) = e^(−2G) + G·(−2)·e^(−2G) = e^(−2G)·(1−2G) = 0 → **G\* = 1/2**
7. S_max = ½ × e^(−1) = **1/(2e) ≈ 0.184 ≈ 18%**

#### Slotted ALOHA：脆弱窗口 = 1 个时隙

只能在槽首发 → 碰撞只可能发生在同一槽内 → 窗口是 Pure 的一半 → 效率恰好翻倍。

**二项版**（N 节点，每节点每槽以概率 p 发）：
1. 槽被有效利用 ⇔ 恰好 1 个节点发送：E(p) = N·p·(1−p)^(N−1)
2. 求导：E'(p) = N(1−p)^(N−2)·[(1−p) − p(N−1)] = N(1−p)^(N−2)·(1−Np) = 0 → **p\* = 1/N**
3. E_max = N·(1/N)·(1−1/N)^(N−1) = (1−1/N)^(N−1) = (1−1/N)^N ÷ (1−1/N) → (1/e) ÷ 1 = **1/e ≈ 36.8%**
4. 数值验证：N=100 时 0.99^99 ≈ 0.3697 ✓（你手算过的）

**泊松版**（对照 Pure 看，更简洁）：
- 成功 ⇔ 恰好 1 次尝试：P(k=1) = G¹·e^(−G)/1! = G·e^(−G)
- S(G) = G·e^(−G)；S'(G) = e^(−G)(1−G) = 0 → **G\* = 1** → S_max = **1/e**

#### 两公式对照（记忆钩）

| | 脆弱窗口 | S(G) | G* | S_max |
|---|---|---|---|---|
| Pure | 2 帧长 | G·e^(−**2**G) | 1/2 | 1/(2e) ≈ 18% |
| Slotted | 1 槽 | G·e^(−**1**G) | 1 | 1/e ≈ 37% |

**指数上那个系数 = 窗口长度**：窗口减半 → 指数减半 → 效率翻倍。

### CSMA 为什么还会碰撞

先听后发（carrier sense）：空闲→发整帧；忙→推迟。
但**监听有传播时延盲区**：A、B 相距远，A 监听空闲开始发；信号还没传到 B，B 监听也是空闲 → B 也发 → 碰撞。听只能**降低**碰撞概率，不能消除。

## Q: CSMA/CD（有线）和 CSMA/CA（无线）的设计分别是什么？

### CSMA/CD（Collision Detection，802.3 以太网）

1. **边发边听**：发送过程中持续检测信道电压
2. **碰撞检测原理**：有线介质上信号电压会叠加，自己发的和别人的重叠 → 电压异常 → 检测到
3. **检测到碰撞 → 立即中止**（发 jam 信号通知大家），不浪费帧的剩余部分
4. **二进制指数退避**：第 i 次碰撞后，从 {0, 1, …, 2^i − 1} 随机取 K，等 K × 512 bit-times 再重发（10Mbps 下 512 bit-time = 51.2μs = 最小帧 64B 的发送时间）。撞得越多随机范围越大 → 自动适应负载
5. **前提 = 最小帧长 64B**（见前面 P5 笔记）：帧必须发到碰撞信号传回来之后还没发完，否则检测不到

### CSMA/CA（Collision Avoidance，802.11 WiFi）

**为什么无线不能 CD**：
1. **发时听不见**：自己发射功率 ≫ 接收信号，边发边收物理上做不到（近远问题）
2. **隐藏终端**：A、C 都在 B 的覆盖内，但 A、C 互相听不见 → 各自监听都"空闲"，同时发 → 在 B 处碰撞。监听根本防不了

**设计（用预约+确认代替检测）**：
1. **DIFS 等待**：信道空闲后先等固定时长 DIFS 才可发
2. **随机退避计数**：DIFS 后不立即发，取随机退避值，信道每空闲一个 slot 减 1，减到 0 才发；信道忙则**冻结**计数（保留剩余值下次接着减）
3. **ACK 确认**：接收方正确收到数据帧后经 SIFS 回 ACK；**没收到 ACK = 认为碰撞**，重传（CD 的"检测"被 ACK 替代）
4. **RTS/CTS 信道预约**（对付隐藏终端）：发数据前先发短帧 RTS（Request To Send），接收方回 CTS（Clear To Send）；两者都携带本次传输**时长**，覆盖范围内所有节点（含隐藏终端——它至少能听到 B 回的 CTS）听到后按该时长**保持沉默** → 相当于虚拟载波监听

**WiFi 完整时序（背顺序）**：

```
信道空闲 → 等 DIFS → 随机退避倒数(忙则冻结) → [可选] RTS⇄CTS 预约
        → 发数据帧 → 接收方经 SIFS 回 ACK → 没收到 ACK ⇒ 判碰撞，重传
```

替代"碰撞检测"的是两件事：**ACK（事后回执，没回执=撞了）+ RTS/CTS（事前预约，降低碰撞发生）**。DIFS/退避是礼貌规则，不是检测替代。

## Q: 802.11、802.3 这些编号是什么？

|---|---|---|
| 802.3 | **以太网**（有线 LAN）| CSMA/CD |

| 802.15 | 蓝牙（无线个域网 WPAN）| 受控/跳频 |

顺带（IP 头 Protocol 字段，L4 会用）：TCP = 6，UDP = 17。

### 受控接入两个代表（一句话机制）

- **Polling 轮询**：中心控制器（master）逐个"点名"邀请节点发送，节点被点到才能发。缺点：控制器=单点故障
- **Token Ring 令牌传递**：一个特殊小帧（令牌）在环上循环，**谁拿到令牌谁发送**，发完把令牌放回。无中心但令牌丢失需要恢复机制

## Q: 隐藏终端问题 + CSMA/CA 怎么修复？

### 隐藏终端（Hidden Terminal）成因链

```
   A ←听得见→ B ←听得见→ C
   A ←—— 互相听不见 ——→ C   （①路径损耗/距离远 ②障碍物遮挡）
```

完整机制（论述题按此顺序写）：
1. A、C 互相听不见（路径损耗或障碍物）
2. **A、C 各自监听信道，结果都是"空闲"**（因为听不见对方的发送）
3. 两者同时向 B 发送 → **碰撞发生在 B 处**（两个信号在 B 叠加）
4. A、C 都不知情——碰撞现场在 B，它们周围信道"看起来"正常

### 802.11 放弃碰撞检测的两条理由（课件原话）

1. 发射时难以同时接收：自己信号强、收到的信号弱（fading），发时"听不见"
2. 隐藏终端的碰撞发生在**接收方 B 处**，A/C 不在碰撞现场，物理上检测不到；B 收到的是叠加乱码，也无法反向通知是谁撞了

### RTS/CTS 修复机制（时间预约，不是编码！）

```
A → B:  RTS   "我要发，时长 T"（帧内带 duration 字段）
B → A:  CTS   "你可以发，大家安静 T"   ← C 听不见 A，但听得见 B 的 CTS！
A → B:  DATA
B → A:  ACK   （经 SIFS）
```

关键：B 的 CTS 替"听不见的 A"完成了广播让路——C 收到 CTS 后沉默 T 时长。

### DCF vs PCF

| | DCF 分布式协调 | PCF 点协调 |
|---|---|---|
| 机制 | CSMA/CA 自由竞争 | 架在 DCF 上，AP 中心**轮询**点名，无竞争 |
| 适合 | Ad Hoc、异步流量 | 语音/多媒体等时间敏感业务 |
| 对应 P10 三大类 | 随机接入 | 受控接入（Polling 在 WiFi 的化身）|

**暴露终端**（exposed terminal，名字记住即可）：与隐藏相反——C 听见 B 正在收 A 的包就不敢发给 D，其实两者不冲突；是 RTS/CTS 的副作用。

## Q: 电路交换 vs 分组交换？数据报 vs 虚电路？

### 包含关系（先分清层级）

```
电路交换 Circuit Switching
分组交换 Packet Switching ──┬── 数据报 Datagram（Internet）
                            └── 虚电路 Virtual Circuit（X.25/Frame Relay/ATM）
```

### P22: 电路 vs 分组

| | 电路交换 | 分组交换 |
|---|---|---|
| 资源 | 端到端**预留独占** | **共享**，统计复用 |
| 连接 | 三阶段：建立→传输→释放 | 无需建立，直接发 |
| 性能 | 有保障（适合语音）| 尽力而为，可能排队/丢包 |
| 浪费点 | 空闲时资源白占 | 缓冲区排队、拥塞丢包 |
| 速率 | **两端必须同速率** | 各自 store-and-forward |

电路交换不适合数据业务的两个理由：① 数据业务突发、连接常空闲（浏览网页大量静默），独占=浪费；② 速率固定，两端必须同速率，数据设备速率差异大适配不了。

### P23: 数据报 vs 虚电路

| | Datagram | Virtual Circuit |
|---|---|---|
| 路由 | 每包独立选路 | 传输前预建路径，全包同路 |
| 包头 | 完整目的地址 | 只带 VCI（各节点查表换号）|
| 到达 | 可能乱序/丢失 | 按序到达 |
| 连接阶段 | 无 | 有（建连→传输→拆除）|
| 资源预留 | 不预留 | **也不预留**（最常考陷阱！）|
| 代表 | Internet | X.25、Frame Relay、ATM |

**三者一句话区分**：电路 = 预留资源 + 固定路径；VC = **不预留资源** + 固定路径（只"记住路"，不"占着路"）；数据报 = 不预留资源 + 每包自选路。

### VC 转发表与 VCI

- 完整地址只在**建连时**用一次（协商路径）；路径信息变成各节点的转发表
- 表项：**(入接口, 入VCI) → (出接口, 出VCI)**，每个节点接力换号
- 好处：数据包只带小号码，头短、转发快

### 链路故障时：VC vs 数据报

- **VC**：路径断了连接就废了——节点丢弃失效表项，**不会自动重建**；要恢复必须端系统重新走建连阶段（重建靠信令，不靠包头地址——VC 包里根本没有完整地址）
- **数据报**：路由协议收敛后，后续包自动走新路径，端系统无感知

### 为什么 Internet 选数据报（"路由器状态"角度，必考论述）

- 数据报路由器**不保存任何每连接状态**，只有按目的前缀转发的路由表 → 简单、可扩展
- VC 路由器要为**每条活动连接**维护 VCI 表项（建立写入、拆除删除）→ 状态随连接数暴涨
- 哲学一句话：**数据报 = 智能在包里（自带地址），路由器无状态；VC = 智能在路由器里（VCI表），路由器有状态**（端到端原则）

## Q: DHCP 四步交互？NAT 怎么工作？

### DHCP（DORA）

```
① Discover  主机广播:"有DHCP服务器吗?"（不是"有哪些地址"——此时连服务器存在都不知道）
② Offer     服务器广播:"给你一个IP"（含IP、租期lifetime、事务ID）
③ Request   主机广播:"我就要这个IP"（广播是因为可能收到多个Offer，让所有服务器知道选了谁）
④ ACK       服务器:"成交，租给你"
```

- 跳过规则：主机记得上次地址 → 可跳过①②
- **Discover 三层地址**：以太网目的 MAC = FF:FF:FF:FF:FF:FF（链路层也广播，主机连网关 MAC 都不知道没法 ARP）；IP: 0.0.0.0 → 255.255.255.255；UDP 端口：客户端 68 → 服务器 67
- 封装链：DHCP → UDP → IP → 以太网广播帧
- 附带配置一次给齐：**网关（第一跳路由器）地址、DNS 服务器地址、子网掩码**
- 租期制（lease）：地址是租的，到期续租；断开即回收 → 地址复用、支持移动用户

### NAT（实际是 NAPT：地址+端口转换）

- 动机：IPv4 耗尽（ICANN 2011 发完最后一块）；私网地址（10/8、172.16/12、192.168/16）不可上公网
- **出去**：(源IP, 源端口) → (NAT公网IP, 新分配端口)，NAT 表记一笔
- **回来**：按键 (目的公网IP, 目的端口) 查表 → 还原成 (内网IP, 内网端口)
- 区分多台内网主机靠**端口号**：10 台设备同时上网 = 10 个不同的分配端口

课件原题：
```
10.0.0.1:3345 → 128.119.40.186:80
过NAT:  S: 138.76.29.7:5001（表项 5001 ↔ 10.0.0.1:3345）
回包:   D: 138.76.29.7:5001 → 查表还原 D: 10.0.0.1:3345
```

- 四个优点：①全组织只需1个公网IP ②内部改地址外界无感 ③换ISP不改内网 ④安全：外部无法直接寻址内网
- **外部无法主动发起连接**：表项是被动建立的（内网先出去才有），没有表项的入包直接丢弃 → NAT 后开服务器需手动"端口映射/转发"

### NAT 破坏端到端原则（论述加分项）

端到端原则 = 智能在两端，网络核心无状态转发，任意端点可直接寻址通信。NAT 的三层破坏：
1. **地址语义**：内网地址只在本地有意义，通信实际是"和 NAT 盒子对话"
2. **中间盒子有每流状态**（正是 P23 批评 VC 的点）：NAT 盒子重启 → 表清空 → 所有活动连接全断；连接数受端口范围封顶
3. **应用受害**：双方都在 NAT 后 → P2P 直连失败（催生 STUN/TURN 穿透，合理推断）；IPsec ESP 加密头部导致 NAT 无法改端口（需 NAT-T）；端口语义超载（既标进程又标主机）

为什么还用：IPv4 耗尽的务实妥协；IPv6（128位）地址够多、无需 NAT，端到端得以恢复。
考试写法：四个优点 + 一条批评（中间盒子有状态、外部无法主动发起）= 有理解不像背书。

## Q: ARP 怎么工作？跨子网 ping 帧怎么变？

### 3 步机制

1. **本地广播** ARP 请求："谁是 x.x.x.x？"（目的 MAC = FF-FF-FF-FF-FF-FF，只在同一子网内）
2. **目标单播回复**："我是，MAC 是 …"（请求方 MAC 已在请求帧里，无需广播）
3. **ARP 缓存**：映射存 cache 复用，有过期时间；**缓存有表项就不再广播**

### 跨子网 ping（最常考）：A(11-11) → 网关(AA-AA) → S(99-99)

| # | 源MAC | 目的MAC | 内容 |
|---|---|---|---|
| 1 | AA-AA... | FF×6 | A 广播 ARP 问**网关**的 MAC（不是问 S！）|
| 2 | 网关 | AA-AA... | ARP 回复 |
| 3 | AA-AA... | **网关MAC** | ping 包，**IP 目的仍是 S** |
| 4 | 网关拆帧→查路由→**在 S 的子网再广播 ARP 问 S**→S 回复→重建帧(源MAC=网关出口, 目的MAC=99-99)转发 |

**三句核心结论**：① IP 地址端到端不变；② MAC 每跳都换（帧每跳拆掉重建，源和目的 MAC 都换）；③ 跨子网时 ARP 问的是**网关**的 MAC。
**口诀**：ARP 逐子网接力——A 在己方子网问网关，网关在对方子网问 S。
**IPv6 对应物**：无 ARP，用 ND（Neighbor Discovery，跑在 ICMPv6 上）：Solicitation / Advertisement / Router Advertisement。
**陷阱**：ARP 不跨路由器（路由器不转发广播）；帧3 的 IP 目的是最终主机不是网关。

## Q: 最长前缀匹配 + 路由聚合

### 规则

多条表项都匹配目的地址时，选**前缀最长（最具体）**的那条；默认路由（/0，otherwise）最短，谁都不匹配才用。比较的是**前缀长度**，不是表项顺序。

### 二进制比法（第三个字节）

```
200.23.16.0/20: 16=00010000 取前4位0001 → 覆盖 .16–.31
200.23.18.0/23: 18=00010010 取前7位0001001 → 覆盖 .18–.19
200.23.0.0/16:  覆盖 200.23.*.*
例: .18.77 → /20✓ /23✓ /16✓ → 取最长/23
    .31.9  → /20✓(31=00011111前4位0001) /23✗ /16✓ → 取/20
```

### 为什么需要它：路由聚合 + 例外

- ISP 通告**聚合前缀**（"200.23.16.0/20 都发我"）→ 一条表项覆盖一堆客户块，路由表不爆炸
- 客户 200.23.18.0/23 **搬家换 ISP** → 新 ISP 追加更具体通告"或 200.23.18.0/23 发我"
- 两条都匹配时，**最长前缀匹配保证走新 ISP**：大路由兜底，小路由纠偏

## Q: IPv4 数据报格式（20 字节典型头）

### 必背 6 字段

| 字段 | 位宽 | 干什么 |
|---|---|---|
| TTL | 8 | 每过路由器减1，减到0丢弃**并回 ICMP Time Exceeded**（traceroute 原理）|
| Protocol | 8 | 上层协议：TCP=6，UDP=17（解复用）|
| Total Length | 16 | 头+数据总字节，最大 64KB |
| Identification | 16 | 同一报的所有分片共用（认亲）|
| Flags | 3 | DF=1 禁分片（超MTU丢）；MF=1 后面还有片（末片=0）|
| Fragment Offset | 13 | 本片数据在原始 payload 的位置 ÷8 |

### 结构字段

- Version(4)=4；**Header Length(4) 单位是 4 字节字**：20字节头→填 **5**（4位最大15×4=60，装得下最长头 20+40 Options）
- Header Checksum(16)：**只校验头不校验数据**；TTL 每跳变 → checksum **每跳重算**
  - 为什么不校验数据：头小且每跳必重算；数据大、端到端只查一次（TCP/UDP checksum 负责）——每跳重算全数据不值得
- Type of Service(8) = Diffserv(6) + ECN(2)；Options 变长很少用

### 开销账

20(IP) + 20(TCP) = **40 字节/包**固定开销 + 应用层头。
例：Total Length=520、Header Length=5 → payload=500 → 减 TCP 头 20 → 应用数据 480。
（注意：8 倍数约束只在 IP 分片时存在，与 TCP 段大小无关。）

## Q: IP 头多大？HL 是什么？MTU 定义在哪一层？

### IPv4 头：20–60 字节（变长，不是 20–40）

- 固定 20 字节 + Options 最多 40 字节 → 总长 **20–60**
- 5 个字（word=4字节）的结构：
  ① Version(4位)+HL(4位)+ToS(8)+Total Length(16)
  ② ID(16)+Flags(3)+Offset(13)
  ③ TTL(8)+Protocol(8)+Checksum(16)
  ④ Source IP(32)　⑤ Destination IP(32)

### HL（Header Length，RFC 里叫 IHL）

- 4 位，**单位 = 4 字节（32位字）**：无 Options 头=20 字节 → HL=**5**；最大 15 → 15×4=**60** 正好盖住最长头
- 为什么需要它：IPv4 头**变长**（Options），接收方必须读 HL 才知道头在哪结束、数据从哪开始
- 为什么单位是 4 字节：4 位只能表示 0–15，按字节计最多 15 字节不够用；按"字"计最多 60 字节正好——**与 Offset 用 8 字节做单位是同一个省位技巧**（13 位 ÷8 单位 → 覆盖 64KB）
- Options 必须填充（pad）到 4 字节的倍数，HL 才能整字计数

### IPv6 头：固定 40 字节

- Version(4)+Traffic Class(8)+Flow Label(20) │ Payload Length(16)+Next Header(8)+Hop Limit(8) │ Src(128位=16B) │ Dst(16B) = 4+4+16+16 = **40**
- 为什么能定长：砍掉了 Options 字段（扩展功能 → **扩展头链**，挂在后面用 Next Header 串接）→ 也就不需要 HL 字段
- 头更大（40>20，因为地址翻倍占 32B）但**字段更少、定长** → 路由器解析更快（这是 IPv6 "faster processing" 动机的来源）

### MTU 定义在哪一层？——L2 的约束，L3 的机制

- **MTU 是链路层属性**：= 该链路技术的帧最大 payload。以太网帧最大 1518B = 14(头) + 1500(payload) + 4(CRC) → **MTU = 1500**
- **分片是 IP 层机制**：路由器比较"IP 数据报 Total Length vs 出接口链路的 MTU"，超了就切
- **因果别搞反**：不是"Offset 在 IP 头所以 MTU 属于 IP 层"，而是——L2 给约束（MTU），L3 出机制（分片）；**Offset/ID/MF 在 IP 头里，是因为执行切分的正是 IP 层**，且切分元数据必须跟着每个分片走
- 为什么 L2 不做分片：帧是逐跳的、原子的，L2 没有端到端重组实体；IP 是最低的端到端层 → 只能在目的主机重组
- 佐证是设计选择：IPv4 选"路由器可分片"，IPv6 选"只有源可分（PMTUD）"——同一个 L2 约束，两种 L3 应对方案

## Q: OSI 7层 vs TCP/IP 5层？封装是什么？（分层视角串联全部知识）

### 两模型对照

| OSI 7层 | 功能 | TCP/IP 5层 | 设备/PDU |
|---|---|---|---|
| 7 Application | 应用请求网络服务 | **Application**（三层合一）| message |
| 6 Presentation | 加密/压缩/格式转换 | ↑ | — |
| 5 Session | 会话建立/同步/检查点 | ↑ | — |
| 4 Transport | 可靠交付、进程到进程 | Transport | **segment**（Ht）|
| 3 Network | 跨网段路由 | Internet | **datagram**（Hn）|
| 2 Data Link | MAC 寻址、成帧 | Link | **frame**（Hl+Tr）|
| 1 Physical | 比特、电缆 | Physical | bits |

- OSI 记忆钩：**P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way
- Presentation/Session 在 Internet 栈中"消失"→ **由应用层自己实现**：加密=TLS、会话=TCP连接管理或应用自己做（登录态/断点续传）
- Internet 不用 OSI 的原因：①那两层被证明非必需 ②OSI 先标准后实现（过度设计），TCP/IP 先跑起来再总结（务实）

### 封装/解封装（套娃）

```
发送端自上而下加头：
  M → [Ht|M] segment → [Hn|[Ht|M]] datagram → [Hl|[Hn|[Ht|M]]|Tr] frame → bits
接收端逐层剥头：每层只看自己的头，剥完交给上层
```

**四 PDU 必背**：message → segment → datagram → frame

### 中间设备各看到第几层（L1/L2/L3 设备）

| 设备 | 层 | 看什么 | 干什么 |
|---|---|---|---|
| 中继器/集线器 | L1 | 什么都不看（只认比特）| 放大重发 |
| 交换机/网桥 | L2 | **目的 MAC** 查表 | 转发端口，重建帧 |
| 路由器 | L3 | **目的 IP** 查转发表 | 拆帧→IP处理→ARP→重建帧 |

**铁律：所有转发设备只看"目的"不看"源"**（源地址只在回信/ICMP报错/NAT回程时用）。

### 路由器逐跳处理全流程（把学过的点全串起来）

```
帧到达 → L2 拆帧查目的MAC是我 → L3 处理：
  ① TTL−1、Header Checksum 重算          （P28：每跳被改的两个字段）
  ② 查转发表：最长前缀匹配选下一跳        （P27）
  ③ MTU 检查：装不下→分片(ID/MF/Offset)   （P21）或 DF=1→丢+ICMP 3/4（P30）
  ④ ARP 解析下一跳 MAC（缓存空才广播）    （P26：逐子网接力）
  ⑤ L2 重建帧：源MAC=本出口，目的MAC=下一跳（P26：IP不变MAC每跳换）
```

### 分层视角回看全部知识点（知识地图）

| 层 | 已学知识点 |
|---|---|
| L1 | 可用性/串并联计算(P6)、传播时延 d/s(P18)、无线三难点：损耗/干扰/多径(P12) |
| L2 | 停等/滑窗利用率(P1-3)、CRC(P4)、CSMA/CD最小帧长(P5)、GBN vs SR(P9)、MAC三大类+ALOHA效率(P10)、以太网帧(P14)、802.11帧四地址(P15) |
| L2↔L3 | ARP/ND(P26)——IP 到 MAC 的翻译官 |
| L3 | IP头格式(P28)、分片(P21)、CIDR/VLSM(P16/17)、最长前缀(P27)、IPv6+隧道(P29)、ICMP(P30)、电路/分组/VC(P22/23)、DHCP+NAT(P24/25，NAT其实是L3/L4盒子) |
| L4 | 传输延迟 L/R、流水线、电路vs分组延迟对比(P18-20)；TCP=6/UDP=17(P28) |
| 跨层 | 封装(P8)、WiFi协议栈：CSMA/CA在MAC、ND在ICMPv6(P11/29) |

### 现实设备合一（合理推断）

家用"路由器" = 路由器(L3, NAT+DHCP服务器) + 交换机(L2, LAN口) + 无线AP(802.11) + 有时modem 的多合一。
**网关是角色不是设备**：= 本子网通往外部的出口 IP（DHCP 发的"第一跳路由器地址"），通常由路由器的 LAN 侧接口充当。

## Q: IPv4 vs IPv6？

| | IPv4 | IPv6 |
|---|---|---|
| 地址 | 32 位 | 128 位 |
| 头 | 20–60 字节变长 | **40 字节定长** |
| Checksum | 有（每跳重算）| **砍掉**（交给上层）|
| 分片 | 路由器可分片 | **路由器不分片**，只有源主机能分（PMTUD）|
| Options | 头内变长字段 | 砍掉 → 扩展头 |
| TTL | TTL | 改名 Hop Limit |
| Protocol | Protocol | 改名 Next Header |
| 新字段 | — | Flow Label(20) + Priority |
| 地址解析 | ARP | ND（ICMPv6 承载）|

**PMTUD**（Path MTU Discovery）：源发"别分我"的包 → 瓶颈路由器**①丢包 ②回 ICMP "Fragmentation Needed / Packet Too Big"（附自己 MTU）** → 源把包改小重发。哲学：IPv6 把每跳负担全砍掉（checksum、分片、options），路由器只看目的转发。

**过渡 = Tunneling**：没有 flag day，渐进过渡。**IPv6 包整个塞进 IPv4 数据报当 payload**（谁过河谁装信封）；外层信封 IPv4 → 中间 IPv4 路由器只看外层、看不见也不需要看内层。现状：Google ~40% 客户端 IPv6（2023）。

## Q: ICMP 是什么？就是 ping 吗？

**不是。ICMP = IP 层的信使/报错系统**，自己装在 IP 包里运（Protocol=1）：

```
ICMP
├── 查询类: ping = Echo request(8/0) ⇄ Echo reply(0/0)
└── 差错类(被动回信):
    ├── TTL 减到 0     → 11/0 Time Exceeded（traceroute 靠它）
    ├── 目的不可达     → 3/x Destination Unreachable
    └── 包超MTU且DF=1 → 3/4 Fragmentation Needed（PMTUD 靠它）
```

- 差错消息携带**触发差错的原始 IP 头前 8 字节** → 源知道是哪个包出事，前 8 字节含端口号可定位到具体进程
- **traceroute**：故意发 TTL=1,2,3… 的探测包；第 k 跳把 TTL 减到 0 → 丢弃并回 11/0，源从回信源地址学到第 k 跳是谁 → 逐跳"钓"出整条路径

## Q: 差错检测 vs 纠错（P13）

两条技术路线：
- **ARQ**：检错→重传（停等/GBN/SR，靠超时或 NAK）
- **FEC 前向纠错**：多发冗余位，收端自己纠错不重传（Hamming、Reed-Solomon）

| 码 | 检错 | 纠错 |
|---|---|---|
| 单比特奇偶 | 只能检**奇数**个位错 | ❌ |
| **二维奇偶**（行+列校验位）| ✅ | ✅ **纠单比特**：行校验错+列校验错→交叉点即错位，翻转纠正 |
| **CRC** | ✅ 强（所有 < r+1 位突发错）| ❌ 只检不纠；实际用于**以太网和 802.11 WiFi** |

## Q: 以太网帧结构（P14）

```
| Preamble | 目的MAC | 源MAC | Type | Data(payload) | CRC |
   8字节      6字节     6字节   2字节   46–1500字节     4字节
```

- **Preamble 8字节**：7×`10101010` + 1×`10101011`。作用=**同步收发双方时钟**；末字节叫 **SFD 帧起始定界符**，结尾连续两个 `11` 表示"帧正文从下一字节开始"（是**开始**标志，不是结束）
- 目的 MAC=自己或广播(FF×6) 才上交网络层，否则丢
- **Type 2字节**：上层协议（IP等），用于向上解复用（对应 IP 头 Protocol 字段，但在 L2）
- **Data 46–1500**：下限 46 为凑最小帧 64 字节（64 = 14 以太网帧头[目的6+源6+Type2] + 46 + CRC4），不足要 padding——因为帧 <64 字节时 CSMA/CD 冲突检测失效（P5）；上限 1500 = MTU
- 以太网 = **unreliable（无 ACK/NAK）+ connectionless（无握手）**，可靠性交给 TCP；MAC 协议 = CSMA/CD
- ⚠️ 易错：**CSMA/CD** = Carrier Sense Multiple Access / Collision Detection（随机接入）；**CDMA** = Code Division Multiple Access 码分多址（信道划分）。两者无关，别写混

## Q: 802.11 帧的 4 个地址字段（P15）

| 字段 | 含义 |
|---|---|
| Address 1 | **接收方** MAC（收这帧的无线主机或 AP）|
| Address 2 | **发送方** MAC（发这帧的无线主机或 AP）|
| Address 3 | **AP 所连路由器接口**的 MAC（端到端的最终目的/源，用于跨子网）|
| Address 4 | **仅 Ad Hoc 模式**使用 |

为什么要 4 个（对照 P26）：以太网每跳重建帧只需源/目的 2 个 MAC；WiFi 的 STA→AP 一跳里，A1/A2 管"这一跳谁发给谁"，A3 管"最终要去哪"（AP 是 L2 中转，不跨子网）。

### AP vs 路由器（不是一个东西！）

| | AP | 路由器 |
|---|---|---|
| 层 | **L2**（带无线口的网桥/交换机）| **L3** |
| 看 | 目的 MAC | 目的 IP |
| 干什么 | **翻译介质**：802.11 无线帧 ↔ 802.3 以太网帧，不跨子网 | 跨子网转发（查表/TTL−1/ARP/重建帧）|

AP 不是网卡（网卡是主机的一部分；AP 是独立中转设备）。家用"无线路由器"= 路由器+AP+交换机三合一才造成混淆；企业网是独立设备：STA ══AP══交换机══路由器══Internet。
