## 📋 问题总结

### 1. 子 Agent 任务设计过重

**问题描述**：
- 单个子 Agent 任务包含过多修改点（超过 3 个文件/逻辑点）
- 子 Agent 在复杂任务中容易超出 token 预算或触发安全限制
- 任务失败后难以定位具体是哪个环节出错

**典型案例**：
- P2-13（深色主题）：需要创建主题文件 + 修改多个视图 + 处理资源引用
- P2-14（加载状态）：需要创建组件 + 修改服务 + 集成多个 ViewModel
- P2-15（快捷键）：需要修改服务 + 多个 ViewModel + 状态栏

**改进方向**：
- 每个子 Agent 任务限制在 **1-2 个文件修改** 或 **1 个完整功能点**
- 使用迭代文档作为进度接力点，支持多轮子 Agent 执行
- 主 Agent 负责任务拆分和进度追踪，而非直接执行

---

### 2. 子 Agent 过度读取文件

**问题描述**：
- 子 Agent 在修改前反复读取同一文件（超过 3-5 次）
- 读取范围过大（整个文件而非目标区域）
- 缺乏明确的操作指令，导致探索性读取过多

**典型案例**：
- 某些子 Agent 在执行简单替换时，先读取整个文件，再读取目标区域，再验证结果
- 对于已知结构的文件，仍然进行全量读取

**改进方向**：
- 在 subAgent.md 中明确规定：**最多读取 2 次**（1 次确认结构，1 次验证结果）
- 提供精确的行号范围和替换内容
- 使用 `str_replace` 而非全量重写

---

### 3. 主 Agent 承担过多执行工作

**问题描述**：
- 主 Agent 直接执行文件修改、编译验证等操作
- 占用了大量 context window，导致后续任务空间不足
- 未能充分利用子 Agent 的并行能力

**改进方向**：
- 主 Agent 角色定位：**架构师 + 协调者**
  - 分析需求，拆分为原子任务
  - 编写清晰的迭代文档
  - 分发子 Agent 任务
  - 验证子 Agent 结果
  - 更新进度文档
- 子 Agent 角色定位：**执行者**
  - 严格按照迭代文档执行
  - 完成后更新文档标记
  - 遇到问题立即停止并报告

---

### 4. 迭代文档使用不充分

**问题描述**：
- TODO.md 和 STATUS.md 更新不及时
- 缺乏详细的任务拆分说明
- 子 Agent 无法从文档中获取足够的上下文

**改进方向**：
- 在任务分发前，先更新迭代文档，明确：
  - 任务目标和验收标准
  - 需要修改的文件和行号
  - 预期代码变更
  - 依赖关系和顺序
- 子 Agent 完成后，立即更新文档标记状态

## 📋 Geo 模块复盘（2026-11-14）

### 问题总结

#### 1. SDK 依赖管理问题（3 个错误）

**问题描述**：
- ERR-001: 重复类冲突（3dmap + location SDK）
- ERR-009: 版本号不存在（猜测版本号）
- ERR-010: Maven 仓库未配置（高德 SDK 不在标准仓库）

**影响**：
- 编译失败 3 次
- 浪费约 15 分钟反复试错

**改进方向**：
- 建立 SDK 版本验证流程
- 升级前必须查阅 Maven Central
- 不要猜测版本号

---

#### 2. SDK API 使用问题（4 个错误）

**问题描述**：
- ERR-002/003: POI 类包路径错误（3 轮修正）
- ERR-004/007: 方法名错误（getErrorDetail → getErrorInfo）
- ERR-005/006: 异常处理缺失（PoiSearch 构造函数）

**影响**：
- 编译失败 6 次
- 浪费约 30 分钟反复修正

**改进方向**：
- 不要猜测 SDK 的包路径和方法名
- 必须查阅官方 API 文档
- 使用 IDE 的代码提示

---

#### 3. UI 布局问题（1 个错误）

**问题描述**：
- ERR-008: 分类按钮显示不全

**影响**：
- UI 体验差，按钮文字被截断

**改进方向**：
- 建立 UI 组件设计规范
- 按钮高度至少 36dp，字体至少 13sp
