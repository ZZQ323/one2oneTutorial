## 二、答题模板 + 标准答案

### 题型1：威胁→服务→机制分析

**题目特征**：
- 看到：XXX happened, analyze threat, service, mechanism
- 关键词：security incident, attack, breach

**答题模板**：
```
Threat: [威胁]
Service compromised: [服务]
Mechanism: [机制]
```

**场景对照表**：

| 场景 | Threat（威胁） | Service（服务） | Mechanism（机制） |
|------|---------------|----------------|------------------|
| 数据被偷看 | Eavesdropping | Confidentiality | Encryption (AES/TLS) |
| 数据被篡改 | Tampering | Integrity | MAC / Digital Signature |
| 身份被冒充 | Impersonation | Authentication | Certificate / Signature |
| 发送被否认 | Denial | Non-repudiation | Digital Signature |
| 未授权访问 | Unauthorized access | Access Control | RBAC / ACL |

**例题1**：Email被冒充发送

❌ 错误答案：
```
Threat: Tampering
Service: Integrity
Mechanism: Digital Signature
```
（这是"数据被篡改"的答案，不是"身份被冒充"）

✅ 标准答案：
```
Threat: Email impersonation / spoofing
Service compromised: Authentication (entity authentication failed)
Mechanism: Digital Signature or Certificate (e.g., S/MIME, PGP to verify sender identity)
```

**例题2**：数据库被未授权访问

❌ 错误答案：
```
Threat: Eavesdropping
Service: Confidentiality
Mechanism: Encryption
```
（这是"数据被偷看"的答案，不是"未授权访问"）

✅ 标准答案：
```
Threat: Unauthorized access
Service compromised: Access Control (authorization failed)
Mechanism: Access Control Model (e.g., RBAC, ACL to restrict permissions)
```

**关键区分**：
- **Confidentiality（机密性）**: 防止**未授权泄露**（数据在传输中被偷看）
- **Access Control（访问控制）**: 防止**未授权访问**（没有权限的人进入系统）

### 题型2：CBC vs CTR 对比

**题目特征**：
- 看到：one bit error / block lost / update, which mode better?
- 关键词：error propagation, efficiency, database

**答题模板**：
```
[CTR/CBC] is better.
- CBC: [2 blocks / missing 1 + garbled 1 / re-encrypt all]
- CTR: [1 block / all wrong / only modify one]
```

**例题1**：one bit error, which mode has less error propagation?

✅ 标准答案：
```
CTR has less error propagation.

In CBC mode, two blocks are affected:
- Current block is completely garbled
- Next block has the corresponding bit flipped

In CTR mode, only one block is affected:
- Only the corresponding bit in that block is flipped
```

**例题2**：block lost, which mode has less error propagation?

✅ 标准答案：
```
CBC has less error propagation.

In CBC mode:
- One block is missing
- One block is garbled
- Subsequent blocks decrypt correctly (though shifted)

In CTR mode:
- All subsequent blocks are wrong
- Counter desynchronization
```

**例题3**：update records efficiently, which mode?

✅ 标准答案：
```
CTR is more efficient.

In CBC mode:
- Updating a record requires re-encrypting all subsequent blocks
- Due to chaining dependency (Cᵢ depends on Cᵢ₋₁)

In CTR mode:
- Only the corresponding block needs to be modified
- Each block is encrypted independently
```

### 题型3：CTR做MAC不安全

**题目特征**：
- 看到：CTR as MAC, why not secure?
- 关键词：MAC, CTR, forge, modify

**答题模板**：
```
Not secure because:
1. Known-plaintext attack: KS = C ⊕ P
2. Forge: C' = C ⊕ P ⊕ P'
3. MAC unchanged (independent blocks)
```

**标准答案**：
```
CTR MAC is not secure because of known-plaintext attack.

If the attacker knows plaintext P and ciphertext C, they can:

1. Recover the keystream:
   KS = C ⊕ P

2. Forge a new ciphertext to change plaintext from P to P':
   C' = C ⊕ P ⊕ P'

3. Since CTR encrypts each block independently, the MAC value (last ciphertext block) remains unchanged, so the modification is not detected.
```

**关键公式**：
- 恢复密钥流：KS = C ⊕ P
- 伪造密文：C' = C ⊕ P ⊕ P'

### 题型4：MAC不可否认性

**题目特征**：
- 看到：Can MAC provide non-repudiation?
- 关键词：non-repudiation, MAC, symmetric

**答题模板**：
```
No.
- MAC uses symmetric key (shared)
- Both parties can generate MAC
- Cannot prove who sent
```

**标准答案**：
```
No.

MAC uses a symmetric key shared between two parties. Since both parties can generate the same MAC value, it cannot prove who sent the message. Therefore, MAC cannot provide non-repudiation.

Only digital signature (asymmetric cryptography) can provide non-repudiation, because only the private key holder can generate the signature.
```

**关键术语**：
- symmetric key（对称密钥）
- shared between two parties（双方共享）
- both can generate（双方都能生成）
- cannot prove who sent（不能证明发送者）

### 题型5：RSA签名长度

**题目特征**：
- 看到：Largest message for RSA signature?
- 关键词：largest message, sign, hash

**答题模板**：
```
- Message must be < n
- Hash first, then sign (hash-then-sign)
```

**标准答案**：
```
The largest message we can directly sign is less than n (otherwise modular arithmetic fails).

In practice, we hash the message first using a hash function (e.g., SHA-256), then sign the hash value. This allows us to sign messages of any length.

This is called "hash-then-sign".
```

**关键术语**：
- message < n（消息小于n）
- hash function（哈希函数，不是hash map!）
- hash-then-sign（先哈希再签名）

**常见错误**：
- ❌ hash map（这是数据结构）
- ✅ hash function（这是密码学）

### 题型6：证明文件相同

**题目特征**：
- 看到：Prove two files are the same?
- 关键词：prove same, integrity, compare

**答题模板**：
```
- Calculate hash of both files
- Compare hash values
- If identical → same file
```

**标准答案**：
```
Calculate the hash value (e.g., SHA-256) of both pictures.

If the hash values are identical, the two pictures are the same (with negligible collision probability).
```

**关键术语**：
- hash function（哈希函数）
- calculate hash（计算哈希值）
- compare（比较）
- identical（相同）

**常见错误**：
- ❌ signature（不需要证明来源）
- ❌ from the same origin（不准确）
- ✅ hash function（用哈希函数验证）

### 题型7：认证协议分析

**题目特征**：
- 看到：Analyze authentication protocol
- 关键词：protocol, nonce, signature, unilateral, mutual

**答题模板**：
```
Need: freshness + data origin auth

Message 1: [分析]
- Freshness: Yes/No
- Data origin auth: Yes/No
- Conclusion: [谁] authenticated

Message 2: [分析]
...

Conclusion: Unilateral / Mutual authentication
```

**标准答案**：
```
Entity authentication requires:
1. Freshness (using nonce/timestamp to prevent replay)
2. Data origin authentication (using signature to prove sender)

Message 1: A→B: RA, (RA)^A_sign
- Freshness: ❌ (RA is generated by A, no guarantee of freshness)
- Data origin auth: ✅ (A signed RA)
- Conclusion: A is NOT authenticated to B

Message 2: A←B: RB, (RA)^B_sign
- Freshness: ✅ (RB is fresh nonce from B)
- Data origin auth: ✅ (B signed RA)
- Conclusion: B IS authenticated to A

Message 3: A→B: (RB)^B_enc
- Freshness: ✅ (RB is fresh)
- Data origin auth: ❌ (anyone can encrypt with B's public key)
- Conclusion: A is NOT authenticated to B

Overall: This is unilateral authentication (B authenticated to A only).
```

**关键术语**：
- freshness（实时性）
- data origin authentication（数据来源认证）
- nonce / timestamp（防重放）
- signature（证明来源）
- unilateral authentication（单方认证）
- mutual authentication（双向认证）
