## 二、遗漏的题型（⚠️ 需要补充）

### 1. 认证协议分析（2023 Q6独有）

**题目**: 分析认证协议的安全性，讨论freshness和data origin authentication

**关键概念**:
- **Entity Authentication**: 需要 freshness + data origin authentication
- **Freshness**: 用nonce/时间戳防止重放
- **Data origin auth**: 用签名证明消息来源
- **Unilateral vs Mutual**: 单方认证 vs 双向认证

**2023 Q6协议**:
```
1. A→B: RA, (RA)_A^sign      // A发送nonce+签名
2. A←B: RB, (RA)_B^sign      // B发送nonce+签名A的nonce
3. A→B: (RB)_B^enc           // A用B的公钥加密B的nonce
```

**分析**:
- A没有认证给B（M1没有freshness，M3没有data origin auth）
- B认证给A（有freshness+签名）
- 这是**单方认证**（B认证给A）

**你需要**: 理解如何分析认证协议，判断哪方被认证、是否有freshness

### 2. CBC-MAC构造分析（2023 Q5c）

**题目**: 能否用CBC/CTR模式构造MAC？为什么？

**答案**:
- CBC模式可以构造CBC-MAC（最后一个密文块作为MAC）
- CTR模式**不能**构造安全的MAC（已知明文→恢复密钥流→伪造）

**你的资料**: 术语速查表 §七 已包含CTR做MAC不安全，但需要补充**为什么CBC可以**

---

### 3. 对称 vs 非对称提供不可否认性（2023 Q7c）

**题目**: 对称密码系统能提供不可否认性吗？

**答案**: ❌ 不能。对称密钥双方共享，任何人都能生成消息，无法证明发送者。

**你的资料**: 术语速查表 §七 已包含，但需要强调**为什么**

## 三、建议补充的内容

### 1. 认证协议分析框架

```
分析步骤:
1. 检查每步消息: 是否有nonce/timestamp？(freshness)
2. 检查签名: 谁签名了什么？(data origin auth)
3. 判断认证方向: A→B? B→A? 双向？
4. 结论: 单方/双向认证，是否安全
```

### 2. CBC-MAC vs CTR-MAC

| 模式 | 能否做MAC | 原因 |
|------|-----------|------|
| CBC | ✅ 可以 | 链式依赖，修改会被发现 |
| CTR | ❌ 不安全 | 独立加密，已知明文→恢复密钥流 |

### 3. 对称 vs 非对称

| 特性 | 对称 | 非对称 |
|------|------|--------|
| 不可否认性 | ❌ 不能 | ✅ 能 |
| 原因 | 双方共享密钥 | 私钥唯一 |
