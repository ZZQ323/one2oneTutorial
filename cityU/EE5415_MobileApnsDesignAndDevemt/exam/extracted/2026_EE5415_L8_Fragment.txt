Activity lifecycle
●Preserve user data and state if:
○User temporarily leaves app and then returns
○User is interrupted (for example, a phone call)
○User rotates device
●Avoid memory leaks and app crashes.
When a user moves in and out of our app, the Activity instances in our 
app go through different states,  we call it the Activity lifecycle.

----- page 17 -----
onPause()
●Activity has lost focus (not in foreground)
●A call comes in
●User lock screen
●Split-screen
●System dialogue pop-up
●Activity is still visible, but user is not actively interacting with it
●Counterpart to onResume()
•First time to consider releasing resources (e.g., release lock on Camera)
•Refrain from starting any long running synchronous tasks

----- page 18 -----
onStop()
●Activity is no longer visible to the user
●Release resources that aren’t needed anymore
●Save any persistent state that the user is in the process of 
editing so they don’t lose their work
•Good place to stop refreshing UI, running animations, and other visual changes. 
•Activities in a stopped state are not gone

----- page 21 -----
onDestroy()
●Activity is about to be destroyed, which can be caused by: 
○Activity has finished or been dismissed by the user
○Configuration change (e.g., Rotated, Language switched)
●Perform any final cleanup of resources.
●Don’t rely on this method to save user data (do that earlier)

----- page 51 -----
onAttach()
●Called when a fragment is attached to a context/Activity
●Immediately precedes onCreate()
●onAttach()is called before the fragment has access to its layout, 
so you won’t be overriding this method very often.

----- page 52 -----
onCreateView()
●Called to create the view hierarchy associated with the fragment
●Inflate the fragment layout here and return the root view
Werecommend only inflating the layout in this method

----- page 53 -----
onViewCreated()
●Called when view hierarchy has already been created
●Perform any remaining initialization here (for example, restore state 
from Bundle)

----- page 54 -----
onDestroyView() and onDetach()
●onDestroyView()is called when view hierarchy of fragment is 
removed.
●onDetach()is called when fragment is no longer attached to the 
host.

classMyObserver: LifecycleObserver{
