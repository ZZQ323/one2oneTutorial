Model
•Handles data storage and business logic (e.g., from network requests, 
databases).
•Processes and exposes data to the `ViewModel`.
View
•Interacts with the user; Displays data from the ViewModel
•Notifies the `ViewModel` of user actions (e.g., button clicks) actively.
•Observes `ViewModel` changes to update the UI reactively.
ViewModel
•Holds UI-related data for the `View` and prepares it for display.
•Processes user actions and communicates with the `Model` for data 
operations.
•Exposes observable data streams to the `View` 
(Reactive Programming)

Summary
MVP
Focus: Separates UI from business logic, with the Presenter explicitly coordinating UI 
updates.
Limitation: The Presenter may become overloaded as UI interactions and application 
complexity grow.
MVVM
Focus: Enables reactive UI updates through observable, while ViewModel decouples 
UI state from the Activity lifecycle, allowing state to survive configuration changes 
without being tied to a specific Activity instance.
Limitation: Without well-designed state management, multiple independent 
observable data fields may lead to complex data flows and bloated ViewModels.
MVI
Focus: Emphasizes explicit UI states and Unidirectional Data Flow (UDF), making 
state transitions more predictable and traceableto ensure state consistency.
Limitation: Managing immutable states and intents may introduce additional 
complexity
Key Takeaway: There is no universally best architecture. 
Choose the approach that best manages your application's complexity and requirements.
