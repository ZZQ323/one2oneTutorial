
## 二、对称加密详解

### 2.1 DES（Data Encryption Standard）

**基本信息**：
- 密钥：56 bit（64 bit 含 8 bit 奇偶校验）
- 分组：64 bit
- 轮数：16 轮
- 状态：**已不安全**（暴力破解 2^55 次）

**计算流程**：
```
64 bit 明文
  ↓ 初始置换 IP
  ↓ 16 轮 Feistel 网络（每轮：扩展、S盒替换、P盒置换、XOR密钥）
  ↓ 逆初始置换 IP⁻¹
64 bit 密文
```

**考试要点**：
- 密钥长度 56 bit（不是 64）
- 暴力破解平均 2^55 次
- 已被 AES 取代

---

### 2.2 AES（Advanced Encryption Standard）

**基本信息**：
- 密钥：128/192/256 bit（可选）
- 分组：128 bit（固定）
- 轮数：10/12/14 轮（对应密钥长度）
- 状态：**当前标准**

**计算流程**：
```
128 bit 明文（4×4 字节矩阵）
  ↓ 初始轮密钥加
  ↓ 9/11/13 轮（每轮 4 步）：
  │   1. ByteSub（S 盒替换）
  │   2. ShiftRow（行移位）
  │   3. MixColumn（列混合）
  │   4. AddRoundKey（轮密钥 XOR）
  ↓ 最后一轮（无 MixColumn）
128 bit 密文
```

**密钥长度 vs 分组大小**：
- 分组大小 = 128 bit（固定）= 每次处理多少数据
- 密钥长度 = 128/192/256 bit（可选）= 钥匙多复杂
- 类比：箱子大小固定，但锁可以更复杂

**考试要点**：
- 分组 128 bit（固定）
- 密钥 128/192/256 bit
- 轮数 10/12/14

### 2.3 工作模式（Mode of Operation）

#### CBC（Cipher Block Chaining）

**加密**：
```
C₀ = E_K(P₀ ⊕ IV)
C₁ = E_K(P₁ ⊕ C₀)
C₂ = E_K(P₂ ⊕ C₁)
```

**解密**：
```
P₀ = IV ⊕ D_K(C₀)
P₁ = C₀ ⊕ D_K(C₁)
P₂ = C₁ ⊕ D_K(C₂)
```

**特点**：
- ✅ 相同明文块加密结果不同（依赖前文）
- ❌ 链式依赖：更新一个块需重加密后续
- ❌ 错误传播：1 bit 错 → 2 块乱（当前块全乱 + 下一块对应位翻转）
- ❌ 块丢失：丢 1 块 → 缺 1 + 乱 1
- ✅ MAC 相对安全（链式依赖，修改会被发现）

**应用场景**：文件加密、SSL/TLS（旧版）

---

#### CTR（Counter Mode）

**加密**：
```
C₀ = P₀ ⊕ E_K(IV)
C₁ = P₁ ⊕ E_K(IV+1)
C₂ = P₂ ⊕ E_K(IV+2)
```

**解密**：
```
P₀ = C₀ ⊕ E_K(IV)
P₁ = C₁ ⊕ E_K(IV+1)
P₂ = C₂ ⊕ E_K(IV+2)
```

**特点**：
- ✅ 独立加密：可并行
- ✅ 更新高效：只改对应块
- ✅ 错误传播少：1 bit 错 → 1 块对应位翻转
- ❌ 块丢失：丢 1 块 → 后续全错（计数器失同步）
- ❌ MAC 不安全（独立加密，修改不影响 MAC）

**应用场景**：数据库加密、磁盘加密、高性能场景

---

#### 📝 计算题实例：ps1 Q2 (CBC/CTR 模式)

**题目**：4-bit shift cipher, k=3, 明文 P=BOBALICE

**字母表**：A=0000, B=0001, ..., P=1111

**加密函数**：Ek(X) = (X + 3) mod 16

**Q2(a) CBC IV=1100**：
```
C0 = Ek(B⊕IV) = Ek(0001⊕1100) = Ek(1101) = Ek(13) = (13+3) mod 16 = 0 = A
C1 = Ek(O⊕C0) = Ek(1110⊕0000) = Ek(1110) = Ek(14) = (14+3) mod 16 = 1 = B
C2 = Ek(B⊕C1) = Ek(0001⊕0001) = Ek(0000) = Ek(0) = (0+3) mod 16 = 3 = D
C3 = Ek(A⊕C2) = Ek(0000⊕0011) = Ek(0011) = Ek(3) = (3+3) mod 16 = 6 = G
C4 = Ek(L⊕C3) = Ek(1011⊕0110) = Ek(1101) = Ek(13) = 0 = A
C5 = Ek(I⊕C4) = Ek(1000⊕0000) = Ek(1000) = Ek(8) = 11 = L
C6 = Ek(C⊕C5) = Ek(0010⊕1011) = Ek(1001) = Ek(9) = 12 = M
C7 = Ek(E⊕C6) = Ek(0100⊕1100) = Ek(1000) = Ek(8) = 11 = L
```
**答案**：密文 = **ABDGALML**

**Q2(b) CBC IV=0101**：
- 密文 = **HMADLGHG**（不同IV → 完全不同密文）

**Q2(c) CTR counter=9**：
```
C0 = P0 ⊕ Ek(9) = 0001 ⊕ Ek(9) = 0001 ⊕ 1100 = 1101 = N
C1 = P1 ⊕ Ek(10) = 1110 ⊕ 1101 = 0011 = D
C2 = P2 ⊕ Ek(11) = 0001 ⊕ 1110 = 1111 = P
C3 = P3 ⊕ Ek(12) = 0000 ⊕ 1111 = 1111 = P
C4 = P4 ⊕ Ek(13) = 1011 ⊕ 0000 = 1011 = L
C5 = P5 ⊕ Ek(14) = 1000 ⊕ 0001 = 1001 = J
C6 = P6 ⊕ Ek(15) = 0010 ⊕ 0010 = 0000 = A
C7 = P7 ⊕ Ek(0) = 0100 ⊕ 0011 = 0111 = H
```
**答案**：密文 = **NDPPLJAH**

**Q2(d) C3 MSB错误（CBC错误传播）**：
- P3 完全乱码（整个块受影响）
- P4 对应位翻转（只有MSB翻转）
- **结论**：2块受影响（CBC特性）

**Q2(e) C3丢失（CBC块丢失）**：
- P3 乱码（用C4解密，但前一块是C2）
- P4-P6 正确（但整体向前移一位）
- P7 丢失
- **结论**：丢1乱1（CBC特性）

  ```
  H(0111) ⊕ A(0000) = 0111 = H
  E(0100) ⊕ B(0001) = 0101 = F
  ```

#### 📝 计算题实例：ex03 Q2-Q4 (密钥空间)

**Q2: 3DES密钥空间**
- 2个密钥（K1, K2），各56位
- 总长度：56 + 56 = **112位**
- 密钥空间：**2^112**
- 暴力破解：**2^111**（平均一半）

#### IV 是什么？

IV = Initialization Vector（初始化向量）

• 作用：让相同的明文每次加密结果不同（增加随机性）
• 特点：
• 不需要保密（可以公开）
• 每次加密都应该用新的 IV
• 长度通常等于分组大小（如 128 bit）

为什么需要 IV？

• 没有 IV：相同的明文 → 相同的密文（容易被攻击）
• 有 IV：相同的明文 + 不同的 IV → 不同的密文

#### CBC vs CTR 对比表

| 特性 | CBC | CTR |
|------|-----|-----|
| 解密函数 | D_K（解密） | E_K（加密） |
| 依赖关系 | 链式（依赖前密文） | 独立（依赖计数器） |
| 并行加密 | ❌ 不能 | ✅ 能 |
| 1 bit 错误 | 2 块受影响 | 1 块受影响 |
| 块丢失 | 缺 1 乱 1 | 后续全错 |
| 数据库更新 | 需重加密后续 | 只改对应块 |
| MAC 安全性 | ✅ 较安全 | ❌ 不安全 |
| 适用场景 | 文件加密 | 数据库、高性能 |

### 2.4 流密码（Stream Cipher）



#### 基本原理：
```
密钥流 KS = KS₀, KS₁, KS₂, ...（由密钥生成）
加密：Cᵢ = Pᵢ ⊕ KSᵢ
解密：Pᵢ = Cᵢ ⊕ KSᵢ
```

#### OTP（One-Time Pad）
- 密钥流 = 真随机数，长度 = 明文长度
- **完美保密**（无限算力也破不了）
- 缺点：密钥分发困难

**已知明文攻击**：
```
已知：部分明文 P 和密文 C
算出：密钥流 KS = C ⊕ P
伪造：新密文 C' = P_new ⊕ KS = C ⊕ P_old ⊕ P_new
```

**考试要点**：
- OTP 是完美保密（不是计算安全）
- 已知明文攻击：C' = C ⊕ P_old ⊕ P_new

## 三、非对称加密详解

### 3.1 RSA

**数学基础**：大数分解问题（Integer Factorization）
- 已知 n = pq，分解 p 和 q → 困难
- 正向：p × q → n（容易）
- 反向：n → p, q（困难）

**密钥生成**：
```
1. 选大素数 p, q
2. n = p × q
3. φ(n) = (p-1)(q-1)
4. 选 e 使 gcd(e, φ(n)) = 1
5. 求 d 使 ed ≡ 1 (mod φ(n))

公钥：(n, e)
私钥：(n, d)
```

**加密**：
```
C = M^e mod n（用公钥 e 加密）
```

**解密**：
```
M = C^d mod n（用私钥 d 解密）
```

**签名**：
```
S = M^d mod n（用私钥 d 签名）
```

**验证**：
```
M = S^e mod n（用公钥 e 验证）
```

**应用场景**：
- 加密传输：公钥加密，私钥解密
- 数字签名：私钥签名，公钥验证
- TLS/SSL、SSH、数字证书

**限制**：
- 消息必须 < n
- 大消息 → 先 Hash 再签名

---

### 3.2 ElGamal

**数学基础**：离散对数问题（Discrete Logarithm Problem, DLP）
- 已知 y = g^x mod p，求 x → 困难
- 正向：g^x mod p → y（容易，用快速幂）
- 反向：y → x（困难）

**密钥生成**：
```
1. 选大素数 p
2. 选生成元 g（g < p）
3. 选私钥 x（x < p）
4. 算公钥 y = g^x mod p

公钥：(p, g, y)
私钥：x
```

**加密**：
```
1. 选随机数 r
2. c₁ = g^r mod p
3. c₂ = M · y^r mod p
密文：(c₁, c₂)
```

**解密**：
```
M = c₂ · (c₁^x)^(-1) mod p
```

**安全性**：
- 攻击者知道 (p, g, y, c₁, c₂)
- 要求 x，需解 DLP：y = g^x mod p → 求 x
- DLP 困难 → ElGamal 安全

**应用场景**：
- 加密传输
- 数字签名（ElGamal Signature）
- GPG/PGP（部分实现）

---

### 3.3 Diffie-Hellman（密钥交换）

**数学基础**：离散对数问题（DLP）

**协议流程**：
```
公开参数：p, g

Alice:
  选私钥 x
  算公钥 A = g^x mod p
  发送 A → Bob

Bob:
  选私钥 y
  算公钥 B = g^y mod p
  发送 B → Alice

Alice 计算共享密钥：K = B^x mod p
Bob 计算共享密钥：K = A^y mod p

结果：K = g^xy mod p（双方相同）
```

**中间人攻击（MitM）**：
```
Alice ←→ Eve ←→ Bob

Eve 拦截 A，发送 A' = g^x' 给 Bob
Eve 拦截 B，发送 B' = g^y' 给 Alice

Alice 计算 K₁ = (B')^x = g^xy'
Bob 计算 K₂ = (A')^y = g^x'y
Eve 知道 K₁ 和 K₂

结果：Alice 和 Eve 共享 K₁，Bob 和 Eve 共享 K₂
Eve 可以解密、修改、重加密
```

**防护**：
- 添加数字签名：Sign(A, B, timestamp)
- 需要 CA 证书或预共享公钥
- 时间戳防重放

---

### 3.4 非对称加密对比

| 算法 | 数学难题 | 密钥生成 | 加密 | 签名 | 应用 |
|------|----------|----------|------|------|------|
| RSA | 大数分解 | n=pq, φ(n), ed≡1 | C=M^e | S=M^d | TLS, SSH, 证书 |
| ElGamal | 离散对数 | y=g^x mod p | (g^r, M·y^r) | (r, s) | GPG, PGP |
| DH | 离散对数 | A=g^x, B=g^y | 密钥交换 | 无 | TLS, SSH, IPsec |
| ECC | 椭圆曲线 DLP | Q=d·G | 类似 ElGamal | ECDSA | 移动端、IoT |

## 四、Hash 函数详解

### 4.1 基本概念

**定义**：
```
Hash: {0,1}* → {0,1}^n
输入：任意长度
输出：固定长度（n bit）
```

**性质**：
1. **单向性（Pre-image resistance）**：已知 h，难找 x 使 Hash(x) = h
2. **抗第二原像（Second pre-image resistance）**：已知 x，难找 y ≠ x 使 Hash(y) = Hash(x)
3. **抗碰撞（Collision resistance）**：难找任意 x ≠ y 使 Hash(x) = Hash(y)

**关系**：
```
抗碰撞 → 抗第二原像 → 单向性
（强 → 弱）
```

---

### 4.2 常见 Hash 算法

| 算法 | 输出长度 | 状态 | 应用 |
|------|----------|------|------|
| MD5 | 128 bit | ❌ 已不安全（可碰撞） | 文件校验（非安全场景） |
| SHA-1 | 160 bit | ❌ 已不安全（可碰撞） | 旧版 TLS、Git（旧） |
| SHA-256 | 256 bit | ✅ 安全 | TLS、Bitcoin、数字证书 |
| SHA-3 | 可变 | ✅ 安全 | 新标准 |

**MD5 计算流程**（你记得的）：
```
输入消息
  ↓ 填充（加 1 位 + 0 + 长度）
  ↓ 分成 512 bit 块
  ↓ 每块 4 轮处理（每轮 16 步）
  ↓ 输出 128 bit Hash
```

**SHA-256 计算流程**：
```
输入消息
  ↓ 填充（类似 MD5）
  ↓ 分成 512 bit 块
  ↓ 每块 64 轮压缩
  ↓ 输出 256 bit Hash
```

---

### 4.3 碰撞攻击（生日攻击）

**生日悖论**：
> 23 人中，有 2 人生日相同的概率 > 50%

**为什么？**
- 不是找"某个特定日期"
- 而是找"任意两人相同"
- 组合数 = C(23,2) = 253 种配对

**类比到 Hash**：
```
n 位 Hash → 2^n 种输出
找碰撞（任意两个相同）→ 约 2^(n/2) 次尝试
```

**计算**：
```
尝试 k 次后，碰撞概率 ≈ k² / 2^(n+1)
当 k = 2^(n/2) 时：
  概率 ≈ (2^(n/2))² / 2^(n+1) = 2^n / 2^(n+1) = 1/2 = 50%
```

**具体例子**：
| Hash | 输出长度 | 碰撞复杂度 |
|------|----------|------------|
| MD5 | 128 bit | 2^64 |
| SHA-1 | 160 bit | 2^80 |
| SHA-256 | 256 bit | 2^128 |

**对比**：
| 攻击类型 | 目标 | 复杂度 |
|----------|------|--------|
| 原像攻击 | 已知 h，找 x 使 Hash(x)=h | 2^n |
| 碰撞攻击 | 找任意 x≠y 使 Hash(x)=Hash(y) | 2^(n/2) |

**直觉**：
- 原像：找"那个特定的 x" → 难（2^n）
- 碰撞：找"任意两个相同的" → 容易（2^(n/2)）
- 就像：找"某人生日是 1 月 1 日" vs 找"任意两人生日相同"

---

### 4.4 Bitcoin 挖矿与 Hash

**挖矿过程**：
```
区块头（包含交易、时间戳、nonce）
  ↓ Hash
h = SHA256(SHA256(区块头))
  ↓ 检查
h < target（目标值）？
  是 → 挖矿成功
  否 → 改 nonce，重试
```

**相关 Hash 性质**：
- **单向性（Pre-image resistance）**：给定 target，找 nonce 使 Hash < target
- 不是碰撞攻击（不是找两个相同的）

**考试陷阱**：
- Bitcoin = 原像攻击（单向性）
- 不是碰撞攻击

## 五、应用协议

### 5.1 数字签名

**目的**：认证 + 完整性 + 不可否认性

**流程**：
```
签名：S = Sign(sk, M)（用私钥）
验证：Verify(pk, S, M) = True/False（用公钥）
```

**常见算法**：
- RSA Signature
- DSA（Digital Signature Algorithm）
- ECDSA（Elliptic Curve DSA）

**应用**：
- 数字证书（X.509）
- 代码签名
- 文档签名

---

### 5.2 MAC（Message Authentication Code）

**目的**：完整性 + 来源认证（但**不能**不可否认）

**流程**：
```
生成：T = MAC(K, M)（用共享密钥）
验证：MAC(K, M) = T？
```

**常见算法**：
- HMAC（基于 Hash）
- CBC-MAC（基于分组密码）

**局限**：
- 对称密钥 → 双方都能生成 → 不能不可否认

**对比数字签名**：
| 特性 | MAC | 数字签名 |
|------|-----|----------|
| 密钥类型 | 对称 | 非对称 |
| 不可否认性 | ❌ 不能 | ✅ 能 |
| 性能 | 快 | 慢 |
| 应用 | 内部通信 | 公开验证 |

---

### 5.3 证书与 CA

**X.509 证书**：
```
证书内容：
  - 版本号
  - 序列号
  - 签名算法
  - 颁发者（CA）
  - 有效期
  - 主体（用户/服务器）
  - 主体公钥
  - CA 签名
```

**CA（Certificate Authority）**：
- 可信第三方
- 签发证书（用 CA 私钥签名）
- 验证身份

**证书链**：
```
根 CA（自签名）
  ↓ 签发
中间 CA
  ↓ 签发
终端证书（服务器/用户）
```

**应用**：
- HTTPS（TLS/SSL）
- 代码签名
- 客户端证书

---

### 5.4 GPG/PGP

**GPG（GNU Privacy Guard）**：
- 开源实现 of PGP
- 混合加密：
  - 对称加密（AES）加密数据
  - 非对称加密（RSA/ElGamal）加密对称密钥
- 数字签名：RSA/DSA/ECDSA
- Web of Trust（去中心化证书）

**流程**：
```
加密：
  1. 生成随机对称密钥 K
  2. 用 K 加密消息：C = AES(K, M)
  3. 用接收者公钥加密 K：K_enc = RSA(pk, K)
  4. 发送 (K_enc, C)

解密：
  1. 用私钥解密 K：K = RSA(sk, K_enc)
  2. 用 K 解密消息：M = AES(K, C)
```

---

### 5.5 TLS/SSL（HTTPS）

**TLS 握手流程**：
```
1. Client Hello（支持的加密套件、随机数）
2. Server Hello（选择加密套件、证书、随机数）
3. Client 验证证书（CA 签名）
4. Client 生成预主密钥，用服务器公钥加密
5. Server 解密预主密钥
6. 双方用预主密钥 + 随机数生成会话密钥
7. 后续通信用会话密钥（对称加密）
```

**加密套件**：
```
TLS_RSA_WITH_AES_128_CBC_SHA256
  │   │    │        │     │
  │   │    │        │     └─ Hash: SHA256
  │   │    │        └─ 模式: CBC
  │   │    └─ 对称加密: AES-128
  │   └─ 密钥交换: RSA
  └─ 协议: TLS
```

## 六、学习 Q&A 汇总

### Q1: AES 密钥长度为什么可以和分组大小不同？

**A**: 两个独立参数：
- 分组大小 = 每次处理多少数据（像"箱子大小"）
- 密钥长度 = 钥匙多复杂（像"钥匙齿数"）
- 箱子大小固定（128 bit），但钥匙可以做得更复杂（128/192/256 bit）

---

### Q2: DES、AES、MD5 分别是什么？

**A**:
- **DES/AES**：对称加密（可以解密）
- **MD5**：Hash（不能反推，单向）
- DES 已不安全（56 bit 密钥）
- AES 当前标准（128/192/256 bit 密钥）
- MD5 已不安全（可碰撞）

---

### Q3: 非对称加密用公钥还是私钥？

**A**:
- **保密通信**：公钥加密，私钥解密
- **数字签名**：私钥签名，公钥验证
- 公钥公开 → 谁都能加密/验证
- 私钥保密 → 只有你能解密/签名

---

### Q4: RSA 分解 n = pq 怎么分解？

**A**:
- 小数字：试除法（一个个质数试）
- 大数字：高级算法（二次筛、数域筛）
- 但仍然极其困难 → RSA 安全性的基础

---

### Q5: e 和 d 的区别？

**A**:
- **e（公钥）**：加密、验证签名
- **d（私钥）**：解密、签名
- 用 e 加密 → 只有 d 能解密（保密）
- 用 d 签名 → 谁都能用 e 验证（认证）

---

### Q6: ElGamal 就是 a = b^c mod n 吗？

**A**: 核心是离散对数问题：
- 公钥：y = g^x mod p
- 私钥：x
- 安全性：从 y 求 x 困难（DLP）

---

### Q7: Hash 相同就一定相同吗？

**A**:
- 理论上：有碰撞可能（鸽巢原理）
- 实际上：好的 Hash（SHA-256）碰撞概率极低
- 考试答案：Hash 相同 → 认为相同（碰撞概率可忽略）

---

### Q8: MAC 和数字签名的区别？

**A**:
| 特性 | MAC | 数字签名 |
|------|-----|----------|
| 密钥 | 对称（共享） | 非对称（公/私钥） |
| 不可否认性 | ❌ 不能 | ✅ 能 |
| 性能 | 快 | 慢 |
| 应用 | 内部通信 | 公开验证 |

---

### Q9: 生日攻击为什么是 2^(n/2)？

**A**:
- 生日悖论：23 人中有 2 人生日相同概率 > 50%
- 找"任意两个相同"比找"特定值"容易
- Hash：n 位输出 → 碰撞需要约 √(2^n) = 2^(n/2) 次

---

### Q10: Bitcoin 挖矿是碰撞攻击吗？

**A**: 不是，是**原像攻击**：
- 给定 target，找 nonce 使 Hash < target
- 这是单向性（pre-image resistance）
- 不是找两个相同的（碰撞）

---

## 七、考试高频考点

### 计算题
1. **对称加密**：CBC/CTR 加密解密、错误传播
2. **数论工具**：快速幂、GCD、逆元、φ(n)
3. **RSA**：密钥生成、加密、签名
4. **ElGamal**：加密、解密
5. **DH**：密钥交换

### 分析题
1. **CBC vs CTR 对比**：错误传播、效率、MAC 安全性
2. **DLP 与 ElGamal 安全性**
3. **MAC vs 数字签名**：不可否认性
4. **Hash 性质**：单向性 vs 抗碰撞

### 判断题陷阱
1. Perfect secrecy ≠ Computationally secure
2. Pre-image ≠ Collision resistance
3. DES 密钥 56 bit（不是 64）
4. 生日攻击 2^(n/2)
5. Bitcoin = 原像攻击（不是碰撞）
