
## pdf任务理解

1. 任务背景

    基因组 GC 含量区域化变化，例如 CpG islands。
    假设基因组可由一个 两状态 HMM 建模：状态 A 和状态 B。
    用 Viterbi 算法把序列分割成不同组成的区域。

2. HMM 参数
    状态 A：AT 偏置，发射概率对 {A,C,G,T} 为 {0.35, 0.15, 0.15, 0.35}。
    状态 B：GC 偏置，发射概率对 {A,C,G,T} 为 {0.15, 0.35, 0.35, 0.15}。
    转移概率：A → B = 0.001，B → A = 0.01。
    初始分布：A、B 各 0.5。
    example.fa 是模拟的 1 Mb 序列：小写碱基来自状态 A，大写碱基来自状态 B。
    真实状态路径在 example.positions 中。

3. HMM 文件格式 (example.hmm)
    第一行：`2 4 ACGT` —— 2个状态，4个符号，符号表ACGT
    第二行：`.5 .5` —— 两个状态的初始概率
    第三行：`.999 .001 .35 .15 .15 .35` —— 状态1的转移概率(到自身0.999, 到状态2 0.001) + 发射概率(A,C,G,T)
    第四行：`.01 .99 .15 .35 .35 .15` —— 状态2的转移概率(到状态1 0.01, 到自身0.99) + 发射概率(A,C,G,T)
    注意：程序必须能解析任意HMM文件，不能硬编码参数。

4. 程序要求
    用 Python 实现 Viterbi 解析器。
    必须包含：初始化、矩阵填充、回溯。
    程序接收两个命令行参数，顺序为： <input HMM file> <input fasta file>
    不能硬编码输入参数，因为测试时会换文件。
    测试文件可能叫 test3.txt、inputdata.fa 等，但都是 FASTA 格式，可能有多行序列或只有两行。
    需要读取 FASTA：第一行以 > 开头是 header，序列从下一行开始。
    在源代码中清楚注释：读文件部分、表生成、表初始化、表填充、回溯部分。

5. 输出格式
    输出连续同状态片段，每行格式：
    ```
    start-position end-position state X
    ```
    例如：
    ```
    1 153 state A
    154 252 state B
    253 1651 state A
    ```
    位置是 1-indexed（不是 0-indexed）。
    运行 example.fa 后，需要输出状态 B 的片段数量。

## 澄清误区

这一题的过程就是Viterbi的过程：
> 每一步记录 K 个状态的最大值，然后通过现有的概率以及转移概率，更新 K+1 位置每个状态的最大概率（K 种情况都要），然后从最后 K 个中选出最大的，就自动是这样一个序列了。然后通过数组记录每一步的前一个位置，这样输出的是逆序答案，最后 reverse 一下就行。

它只有一条 DNA 序列，你要做的是把它按位置切段，判断每一段属于：
- AT 丰富区（状态 A）
- GC 丰富区（状态 B）

“状态 A / 状态 B”只是两个区域标签，不是什么父亲母亲、不是什么两条序列、不是嘌呤嘧啶。
它们只是两个隐藏类别，名字随便起，叫“状态 1 / 状态 2”也一样。


这个题：
- 不是遗传、不是父母、不是两条 DNA。
- 是一条 DNA，两个隐藏区域标签，用 Viterbi 做分割。
- 你对 DP 的理解正确。
- 不需要机器学习，就是算法题。
- 用对数概率避免下溢。
- 填表 → 回溯 → reverse → 合并连续同状态 → 输出分段 → 统计状态 B 段数。
- 不需要训练
- 不需要数据拟合
- 不需要梯度下降
- 不需要神经网络

所有概率都是题目直接给你的：
- 初始概率：A 0.5，B 0.5
- 转移概率：A→B 0.001，B→A 0.01
- 发射概率：状态 A 是 {0.35, 0.15, 0.15, 0.35}，状态 B 是 {0.15, 0.35, 0.35, 0.15}

你要做的只是：
- 读入这些参数；
- 读入 DNA 序列；
- 用 Viterbi 动态规划跑一遍；
- 输出分段结果；
- 统计状态 B 的段数。

这就是一个纯算法题，本质是动态规划。
老师让你用 Python 写，是因为它适合写这种算法，不是让你搞机器学习。
作业里的小写 = 模拟时来自状态 A，大写 = 来自状态 B，这是给你对答案用的。
但程序本身不能看大小写，只能看 A/C/G/T 和 HMM 参数。

## 唯一要小心的几个坑
### 坑 1：概率连乘会下溢

序列长度 1 Mb，一直乘小数，会变成 0。
所以通常用对数概率：
1. 乘法变加法
2. 求最大变成求最大（log 单调）
3. 避免浮点下溢

即：
$log(δ_t(j)) = max_i [ log(δ_{t-1}(i)) + log(a_ij) ] + log(b_j(o_t))$

### 坑 2：位置是 1-indexed

输出时 start 从 1 开始，不是 0。

### 坑 3：不能靠大小写作弊

程序只能根据 A/C/G/T 和 HMM 参数推断，不能看字母大小写。

### 坑 4：读 FASTA 要处理多行

FASTA 可能序列跨多行，要把 > 开头那行之后的所有行拼起来。

### 坑 5：参数顺序

命令行参数是：`python yourscript.py <input HMM file> <input fasta file>`

不能硬编码文件名。

## Python 在这题里的坑

缩进：Python 靠缩进分块，别用 Tab 和空格混着。
浮点下溢：概率连乘 1,000,000 次会变成 0。必须用 math.log，乘法变加法。
log(0)：概率为 0 不能取 log。这里发射和转移都 > 0，没事。但初始化可以用 float('-inf')。
大小写：FASTA 里可能大小写都有，但 HMM 发射只针对 A/C/G/T。读进来后统一 .upper()。
索引：Python 从 0 开始，题目输出要 1-indexed，所以输出时 start+1、end+1。
读 FASTA：第一行 > 开头是 header，后面可能多行序列，要全部拼起来。
命令行参数：用 sys.argv，顺序是 <input HMM file> <input fasta file>，不能写死文件名。
回溯不要存整条路径：每一步只存“前一个状态”，最后再倒推。否则内存会爆。
输出格式：每行 start end state X，状态 B 段数单独输出。
