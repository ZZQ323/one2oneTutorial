Dynamic Host Configuration Protocol (DHCP)
• Application-layer protocol: to automatically configure host 
with IP address, default gateway, DNS, etc (echo Lecture 4)
• DHCP protocol is designed to run over UDP with server 
listening at well-known port 67.
• Client is required to run at well-known port 68.
4

============================================================
第 5 页
============================================================
DHCP Protocol
1. DHCP Discover – client requesting for DHCP server
2. DHCP Offer – server responding to client’s request
3. DHCP Request – client accepting server’s offer
4. DHCP Acknowledge – server confirming the offer
5

============================================================
第 6 页
============================================================
DHCP Discover
• UDP source port 68; destination port 67
• Source IP: 0.0.0.0; destination IP: 255.255.255.255 (IP broadcast)
6

============================================================
第 7 页
============================================================
DHCP Offer
• DHCP servers send DHCP Offer via:
• IP unicast using offered IP as destination address (possible since client’s 
physical address is known); or
• IP broadcast to destination address 255.255.255.255
• The client receives the response on UDP port 68.
7

============================================================
第 8 页
============================================================
DHCP Request
• Client selects one offer and sends DHCP Request which includes the selected 
server identifier.
• DHCP Request is sent to destination address 255.255.255.255 (IP broadcast) 
so that other DHCP servers will also receive it and know that their offers are 
being declined.
• Client still uses source IP 0.0.0.0 since the offer is not confirmed yet.
8

============================================================
第 9 页
============================================================
DHCP Acknowledge
• Similar as DHCP Offer, DHCP Ack is sent via IP unicast or broadcast based 
on the DHCP message broadcast flag.
• Once DHCP Ack is received, the client can start using the offered IP 
address within the duration of the lease time.
9

============================================================
第 10 页
============================================================
DHCP Release
• To extend the lease, the process of DHCP Request/Ack is repeated.
• To end the lease, the client sends DHCP Release via unicast to the server.

• Basically, HTTP consists of request/response messages.
