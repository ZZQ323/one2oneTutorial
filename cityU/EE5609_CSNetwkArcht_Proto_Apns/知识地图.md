## 1. L1 物理层：管"比特怎么过介质"

**核心问题**：信号传播多快？链路活着吗？

- **传播/传输时延(P18)**：T_prop = d/s，T_trans = L/R
  - 题：L=10Kbit、R=100Mbps → 0.1ms（课件）
  - ⚠️ 它是 P1-3（a=T_prop/T_frame）和 P5（最小帧长=2×T_prop×带宽）的原料
- **物理韧性/可用性(P6)**：失效概率 b=1−r；串联乘 r、并联乘 b、混合拆路径
  - 题①课件：6个9 → b=10⁻⁶ → 年停机 31.5s
  - 题②课件：HK—SG(双链路并联)—AU + HK—AU直连，每链路 b=0.05 → 断连概率 0.00261875
  - 题③drill：两独立路径(串联0.1×2)∥(0.2) → 0.19×0.2=**0.038**（你曾错成0.38，量级检查）
  - 题④迁移：0.3×0.04=0.012 ✓
- **无线三难点(P12)**：路径损耗、干扰(2.4GHz共享)、多径传播

## 2. L2 链路层：管"帧怎么过一跳"

**核心问题**：一帧怎么可靠地、不撞车地过一条链路？

### 2a. 流控（滑动窗口，P1-P3）＝ L2协议 × L1参数（⚠️不是纯L1）
- U=1/(1+2a)；N<2a+1 时 U=N/(1+2a)；反推 N=ceil(U_min×(1+2a))
- 本质：用 L1 的传播时延算出"信道里能塞几个帧"

### 2b. 可靠传输 ARQ（P9）
- GBN：接收窗=1，丢帧2→丢弃3,4+重发累积ACK1→发送方从帧2起全部重传
- SR：接收方缓存乱序帧+NAK2→只重传帧2；代价=接收端buffer管理
- 序号空间：GBN≥N+1、SR≥2N（防ACK全丢后新旧歧义）
- 题：帧2丢失场景三问（你漏过"接收方对3,4做什么"）

### 2c. 差错控制（P4,P13）
- 检错：单比特奇偶(只检奇数个错)/二维奇偶(**能纠单比特**:行列交叉定位)/CRC(只检不纠,查<r+1位突发错)
- 纠错路线：FEC(Hamming)不重传 vs ARQ重传
- 题：CRC 计算 D×2^r mod₂ ÷G 取余（P4，前期已过）

### 2d. MAC 争用（P5,P10）
- 三大类：信道划分(TDMA/FDMA/CDMA)│随机接入(ALOHA→S-ALOHA→CSMA→CD/CA)│受控(Polling/Token)
- 效率推导：Slotted Np(1−p)^(N−1)→p*=1/N→**1/e≈37%**；Pure 碰撞窗2帧长→S=Ge^(−2G)→**1/(2e)≈18%**
- 题①：G=2 → e⁻⁴≈1.83%，S=3.66%<18%（拥塞）
- 题②：CSMA/CD 最小帧长 64B = 2×(5×2.5μs+4×2μs)×10Mbps（P5，课件推导）

### 2e. 以太网（P14）
- 帧：Preamble(8B,同步时钟)+SFD(10101011,**开始**标志)│目的/源MAC(6+6)│Type(2)│Data(46-1500)│CRC(4)
- 64=14+46+4：Data下限46是为凑最小帧长（否则CSMA/CD失效）
- unreliable+connectionless：可靠性归TCP
- 交换机=L2设备：只看目的MAC查表转发（帧交换表题：ARP广播→学习端口）

### 2f. WiFi 802.11（P11,P12,P15）
- 架构：STA/AP；BSS(1个AP)→ESS(多BSS,经**有线DS**互联)→路由器→Internet；Infrastructure/Ad Hoc；DCF(CSMA/CA) vs PCF(轮询)
- 隐藏终端4步链：A,C互听不见→各自监听"空闲"→同发→**碰撞在B处**→都不知情
- CSMA/CA：DIFS→退避倒数(忙冻结)→RTS/CTS(duration字段=虚拟载波监听)→数据→SIFS→ACK(无ACK=判碰撞)
- 帧4地址：A1收方/A2发方/A3路由器接口/A4仅AdHoc——因为AP是L2中转，一跳内要同时表达"谁给谁"和"最终去哪"
- 题：隐藏终端4步补全、放弃CD两理由、DCF/PCF归类、层级链填空（你曾误"ESS=互联网"）

## 3. L2↔L3 边界：ARP（P26）——翻译官

- IP→MAC：本地广播问/单播答/缓存复用；**逐子网接力**（A问网关，网关到对方子网再问S）
- 跨子网ping三结论：**IP端到端不变│MAC每跳都换│跨子网ARP问的是网关**
- 题：H1(11-11)→网关(AA)→S(99-99) 首帧问谁+四字段+网关转发三步（拆帧→目的子网ARP→重建帧）
- IPv6 对应物：ND（跑在ICMPv6上）

## 4. L3 网络层：管"包怎么跨网到终点"（考点最密集）

**核心问题**：地址怎么分？包怎么走？走不了怎么办？

### 4a. 交换方式哲学（P22,P23）——L3的"世界观"
- 电路(预留+固定路径) vs 分组(共享统计复用)；分组内：数据报(每包选路,无状态) vs VC(预建路径,VCI换号,**仍不预留**)
- 一句话：数据报=智能在包里,路由器无状态；VC=智能在路由器里,有状态
- 题：电路不适合数据业务两理由(突发空闲+速率必须相同)；VC表项(入接口,入VCI)→(出接口,出VCI)；链路断:VC废掉须端系统重建,数据报自动绕路；Internet选数据报的理由(路由器无每连接状态)

### 4b. IP 地址与子网（P16,P17）
- CIDR四件套：网络地址/广播地址/主机范围/掩码
- VLSM三步：主机+2→最小2的幂=块→**从大到小、游标推进、起点对齐**
- 题①课件：192.0.2.130/26 → 128/191/129-190/255.255.255.192
- 题②课件：193.169.1.0/24 分100/60/30/10台+4条P2P → /25,/26,/27,/28,/30×4
- 题③drill：200.10.5.0/24 分50/20/10/2台（你off-by-one：把主机数当块大小）
- 题④重测：192.168.7.0/24 分120/55/25/5/2台（/30块=4再犯）
- 题⑤微重测：172.16.9.0 IoT6台+P2P×2 → /29+/30+/30 全对 ✓

### 4c. IP 数据报（P28,P21）
- 头字段：TTL(每跳−1)/Protocol(TCP=6,UDP=17)/Total Length/ID/Flags(DF,MF)/Offset(13位,÷8)/Checksum(**只盖头,每跳重算**)/HL(单位4字节,无Options填5)
- 分片：数据8倍数、每片新配20B头、只在目的端重组；**切的是IP的payload=TCP段整个**
- ⚠️ 分片是 **L3机制、L2约束**：MTU=1500来自以太网帧payload上限；动手的是路由器IP层
- 题①课件：4000B/MTU1500→3片,offset 0/185/370
- 题②drill：3200B/MTU800→5片,数据776,offset 0/97/194/291/388,末片MF=0（你全对）
- 题③：HL=5理由/payload 500→应用数据480/TTL64→59/每跳改TTL+checksum

### 4d. 转发（P27）
- 最长前缀匹配：多表项匹配取最长；默认路由=最短(/0)兜底
- 路由聚合+纠偏：ISP通告/20兜底，客户换ISP后新ISP通告/23更具体→最长匹配保证走新家
- 题：200.23.{16.0/20→0, 18.0/23→1, 0.0/16→2, default→3}，4个目的地址全对（含.31.9边界）

### 4e. 接入配套：DHCP+NAT（P24,P25）
- DHCP=DORA四步；Discover三层地址(MAC FF×6/IP 0.0.0.0→255.255.255.255/UDP 68→67)；捎带网关+DNS+掩码；租期制
- NAT=出改(源IP,源port)→(公网IP,新port)记表；回查表还原；靠**端口**区分多主机；表被动建立→外部无法主动连入
- NAT批评=破坏端到端：中间盒子每流有状态、重启全断、P2P需穿透
- 题：四步+跳过①②条件；三层地址微重测；NAT表两方向；原题10.0.0.1:3345→138.76.29.7:5001

### 4f. 差错与诊断：ICMP（P30）+ IPv6（P29）
- ICMP=IP的信使(Protocol=1)：查询类ping(8/0,0/0)│差错类TTL expired(11/0)→traceroute、不可达(3/x)、需分片但DF=1(3/4)→PMTUD；带原始头前8字节(定位进程)
- IPv6：128位/40B定长头/砍checksum砍options砍路由器分片/Hop Limit/Next Header/Flow Label
- PMTUD两步：瓶颈路由器**丢包+回ICMP附MTU**→源改小
- 过渡=Tunneling：**IPv6装进IPv4信封**(谁过河谁装信封)，中间路由器只看外层
- 题：IPv6砍三样/PMTUD两动作/tunneling方向(你曾答反)/traceroute用11/0逐跳钓

### 4g. 延迟三题（P18-P20）——发生在L3转发语境
- 四延迟：processing/queueing/transmission(L/R)/propagation(d/s)
- 流水线：k跳n包(忽略d)= (k+n−1)×T_x；题：S—I—D,4包×300B,5×T_f<100ms→R>120kbps
- 电路 vs 分组：s+x/b+kd vs k(p/b+d)+(x/p−1)p/b；分组更快的条件 x/p+(k−1)p/b < s+x/b

## 5. L4/L5（本课程只到门口，但要会"指认"）

- L4：端口解复用；TCP=6/UDP=17；**以太网不可靠→可靠性最终归TCP**（P14/P13的分层逻辑）
- L5：DHCP/DNS/HTTP 是应用层协议；Presentation/Session被应用层吸收(TLS加密、应用自管会话)
- 跨层模型题（P7,P8）：OSI7层 vs TCP/IP5层对照；四PDU：message→segment→datagram→frame

## 6. 跨层三大思想（论述题的"魂"）

**① 端到端原则**（一根线串起5个点）：
数据报无状态路由器(P23) → IP端到端不变MAC每跳换(P26) → checksum只盖头、数据归TCP(P28/P13) → IPv6干脆砍掉checksum(P29) → NAT破坏它被批评(P25)

**② 分层分工"谁管什么"**：
检错：L2 CRC(逐跳) + L4 TCP checksum(端到端)│重传：L2 ARQ 或 L4 TCP│分片：只有L3│争用：L2 MAC│路由：L3│可靠性最终责任人：L4 TCP

**③ 视角切换（payload 相对论）**：
L2看：整个IP数据报(含IP头TCP头)=帧payload│L3看：TCP段(含TCP头)=IP payload,分片只切它│IP头本身：每片各配新的,永不参与被切

**路由器逐跳五步（一句话串5个知识点）**：
拆帧 → ①TTL−1+checksum重算(P28) → ②最长前缀选下一跳(P27) → ③MTU检查,超了分片或DF=1丢+ICMP(P21/P30) → ④ARP问下一跳MAC(P26) → ⑤重建帧:源MAC=本出口,目的MAC=下一跳(P26) → [若是NAT路由器:改源IP+端口记表(P25)]
